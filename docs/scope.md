# Nearbox 是什么、不是什么

这份文件划边界。它应该很少改；改它就意味着产品方向在变，请同时在 `docs/decisions/` 留一条记录。
`README.md` 描述今天的行为，本文描述不轻易变的意图；两者冲突时以本文为准，然后修正 README 或代码。

标着「待确认」的条目是从代码和 README 里推断出来的，还没有人拍板。

## 一句话

手机记想法，电脑跑 Agent。

## 给谁用

一个人，自己的电脑（一台或几台），自己的手机。不是团队工具，也不是一项服务。

## 核心场景

按重要程度排列。一个功能如果不服务于其中任何一条，先问它为什么该进来。

1. **随手记**：手机上一句话进收集箱，回到电脑前它已经在列表里。
2. **派活**：把一条任务交给本机装好的某个编程 Agent CLI，指定项目目录，实时看输出。
3. **跟进**：Agent 的总结回到这条任务的对话里；接着说的每句话都进同一个会话。
4. **不在电脑前也能开工**：人在手机上、电脑在家里，同一个 Wi-Fi 下能配对、能派活、能看进度、能点「允许」。
5. **多个 Agent 分工**：一条任务里，主 Agent 把子任务委派给别的 Agent。

## 原则

取舍的时候用这几条做判据：

- **只在本机**：数据只在本机用户目录，服务只接受局域网连接，不经过任何云端服务器。
- **不做 Agent 本身**：Nearbox 只调度用户已经装好并登录的 CLI，不接模型 API，不做自己的工具调用循环。
- **手机是薄壳**：手机界面永远由电脑下发，Android 壳只负责找到电脑并打开页面。
- **一个输入框就是整个界面**：新能力优先作为输入框旁的芯片或按钮出现，而不是新页面。
- **按钮说人话**：按钮上写的就是按下去会发生的事。
- **少依赖**：能用几十行写清楚并配上测试的，就不引入库。（待确认）

## 不做什么

- 不做云同步、账号体系、多用户协作。
- 不做通用远程桌面工具（见下面「待定」）。
- 不做代码浏览器或编辑器：看 diff 和终端输出是为了跟进 Agent，不是为了在 Nearbox 里写代码。
- 不做 iOS 原生壳：手机浏览器打开同一个地址即可用。（待确认）
- 暂不做 Windows 以外的桌面端。（待确认）
