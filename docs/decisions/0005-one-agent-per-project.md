# 0005 同一个项目目录同时只跑一个 Agent

- 状态：已采纳
- 日期：2026-09-06（委派时的例外加于 2026-09-07）
- 相关：`src/main/scheduler.ts`、`src/main/runner.ts`；README「关于 Agent 的权限」「Agent 之间互相委派」

## 背景

两个 Agent 同时在一个目录里改文件、跑构建，会互相覆盖、互相把对方的改动当成自己的上下文。
用户从手机上连着派几条任务到同一个项目是常态，不能指望用户自己排。

## 决定

调度器按项目串行：一个项目目录里有运行中的 Agent，后来的进队列等；不同项目之间的并发上限在设置里。
唯一的例外是委派：主 Agent 卡在 `nearbox ask` 等子任务时，不占并发名额，它的项目对它派出的子任务开放——
但只对这些子任务开放，用户排在它后面的任务照样等。

## 后果

- 「同一项目并行跑两个 Agent」的需求不接；想并行就分到两个目录。
- `nextRunnable` 是纯函数，规则全在里面，改调度先改测试。
- 停止主 Agent 会一并停止它的子任务（`activeDescendants`），否则子任务会占着项目目录。
