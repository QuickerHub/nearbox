# 0011 左侧列表按项目分一层段、一行一条任务，不做目录树

- 状态：已采纳
- 日期：2026-09-08
- 相关：`src/renderer/src/ui/TaskList.tsx`、`src/renderer/src/lib/taskList.ts`；README「使用方式」

## 背景

想参考 Cursor Agents 窗口和 Codex 桌面版，把左侧列表做成按目录组织、一行一个对话。原来的列表按「运行中 / 待处理 / 已完成」分组，
混了 run 的状态和 task 的状态，一轮跑完任务就跳组；每行两行文字，项目名在每行重复；等你点允许的运行在列表里看不出来。
Nearbox 的调度按项目串行（0005）、常驻会话按 (Agent, 项目) 保持，项目本来就是工作发生的地方；但用户是一个人，项目数是个位数，
手机记进来的任务还没有项目。两家参照物实际也都只做一层分组加「按时间」切换，不是树。

## 决定

一层分段，不做多级树。顶部两块跨项目的看板「需要你」「运行中」只做镜像，任务自己的那一行留在下面的段里，不因开跑或跑完而移动。
下面是「收集箱」（无项目）一段加每个项目一段，段按项目登记顺序排，不按活跃度重排；段内一行一条任务，项目名只在段头。
一行对应一条任务而不是一段 Agent 会话（README：每条任务就是一段对话）。分组键是 `task.projectId`——下一句话会发到哪——换项目芯片任务就搬段。
项目不到两个时自动扁平；按项目 / 按时间可切换，手机端始终按时间。「新回复」的已读状态记在本设备的 localStorage 里，不进 state.json。

## 后果

- 不做拖动排序、不做多级目录、不按路径推断归属：项目是显式实体，Codex 在 worktree 和长路径上反复出的那类「任务消失」问题这里不存在。
- 已读状态按设备各记一份：手机上看过的，电脑上仍标「新回复」。要跨设备同步得进协议和 state.json，暂不做。
- 一条任务有过运行后仍允许改项目，代价是它会在列表里搬段；是否锁定项目是另一个取舍，这里没有决定。
