# 0004 状态存一个 JSON 文件，运行日志每次一个 JSONL 文件

- 状态：已采纳
- 日期：2026-09-06
- 相关：`src/main/store.ts`、`src/main/runner.ts`；README「数据在哪」

## 背景

要持久化的是任务、项目、运行记录、配对信息、设置，加上每次 Agent 运行的完整事件流。
一个用户、几百条任务的量级；运行日志是只追加、按行独立的 JSON 事件，还要能一边写一边被回放。

## 决定

`data/state.json` 一个文件装全部结构化状态，写入去抖并原子化（先写临时文件再改名），崩在写入中途不会留下半个文件。
每次运行的事件写到 `data/runs/<id>.jsonl`，一行一个事件，回放就是顺序读。运行记录最多保留 300 条。

## 后果

- 不引入数据库，没有迁移脚本；`PersistedState.version` 字段留给以后格式变化时用。
- 单文件全量写，状态大到几 MB 之前都没问题；真到那一步再说，不要提前换存储。
- 用户能直接打开文件看、备份、删掉重来，这和「数据只在本机」是一体的。
- 手机发来的文件另存在 `inbox/<设备名>/`，`state.json` 里只记路径和元数据。
