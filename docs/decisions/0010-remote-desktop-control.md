# 0010 远程桌面控制留不留、留多少

- 状态：待定
- 日期：2026-09-08（功能本身加于 2026-09-06）
- 相关：`src/main/screen.ts`、`src/main/remote.ts`、`src/main/remote-input.ts`、`src/main/input-win.ts`、`src/renderer/src/ui/RemoteView.tsx`、`src/renderer/src/lib/remoteZoom.ts`；设置页「远程控制」

## 背景

2026-09-06 加入了完整的远程桌面：电脑用一个隐藏窗口通过 `getUserMedia` 抓主屏，缩放后编成 JPEG（默认 72 质量、12 fps、最长边 1920，
支持只编码一块区域）经 WebSocket 推给手机；手机上的指针和键盘消息翻译成一行行命令，喂给一个常驻的 PowerShell 进程，
由它 P/Invoke user32 `SendInput` 注入。设置里默认开启，有人连上时电脑弹通知。

当时的想法写在设置页的说明里：「像向日葵一样；因为在同一个应用里，可以边看画面边让 Agent 干活。」

现状：这块代码的体量（主进程约 1000 行加 43 KB 的 `RemoteView.tsx`）和核心的输入框组件相当，但 README 的产品说明里完全没有它；
实际使用中的反馈是操控不方便——在手机屏幕上精确操作电脑桌面，本来就是所有远程桌面软件都没解决好的事。

## 待选

1. **收窄成「看一眼、点一下」。** 保留屏幕流，去掉鼠标键盘注入或只留极少的动作（点一下、按回车、输入一段文字）。
   服务的场景是：Agent 弹了个窗、卡在某个确认上，手机上瞄一眼并解掉。这是 `docs/scope.md` 第 4 条核心场景里真正缺的那一块。
   代价：删掉 `input-win.ts`、`remote-input.ts` 的大部分和 `RemoteView.tsx` 里的操控界面。
2. **继续投入把操控做好。** 手势、虚拟触控板、快捷键面板、区域放大跟随。这条路的终点是一个通用远程桌面工具，
   和「不做通用远程桌面工具」直接冲突，要先改 `docs/scope.md`。
3. **整个移除。** 最省事；失去的是「不在电脑前时看看电脑上发生了什么」，而 Agent 的输出本来就已经流到手机上了。

## 决定

待拍板。选定后把这一节改成决定本身，状态改为「已采纳」，并更新 `docs/scope.md` 的「不做什么」和「待定」两节；
若选 1 或 3，README 不用加内容；若选 2，README 要补一节。
