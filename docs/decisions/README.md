# 决策记录

每个文件回答一个问题：为什么是现在这样。写给三个月后的自己，和每一个新开的 Agent 会话。

## 什么时候写

- 选了 A 没选 B，而 B 看起来同样合理。
- 绕过了某个工具的坑（这种代码最容易被后来人「顺手修掉」）。
- 改动了用户环境里 Nearbox 之外的东西。
- 想做的事超出了 `docs/scope.md`：先写一条「待定」，等人拍板再动手。

不写的：显而易见的实现细节、能从代码注释一眼看懂的东西。

## 怎么写

文件名 `NNNN-english-slug.md`，编号取当前最大值加一。内容用中文，十到二十行。
「待定」的记录在拍板时补全「决定」和「后果」，状态改成「已采纳」；已采纳的记录不再改写：
决定变了就新写一条，把旧的状态改成「已废弃（被 NNNN 取代）」。

```markdown
# NNNN 一句话写出决定本身

- 状态：已采纳 | 待定 | 已废弃（被 NNNN 取代）
- 日期：YYYY-MM-DD
- 相关：`src/main/xxx.ts`；README「章节名」

## 背景

当时面对的问题和约束，两三句。

## 决定

我们怎么做。

## 后果

因此得到了什么、放弃了什么、以后要注意什么。
```

没有单独的索引，文件名就是索引。

## 关于 0001 到 0009

这九条是 2026-09-08 从代码注释、README 和提交历史里追记的，日期写的是决定实际发生的那次提交的日期。
它们描述的是既成事实；如果哪条和你的本意不符，改状态、新写一条，而不是原地改写。
